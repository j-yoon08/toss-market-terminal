# v0.12 First-Run Credential Onboarding Implementation Plan

> **For Hermes:** Implement task-by-task with focused tests before the broad release suite.

**Goal:** Let a new user run `toss-market`, enter Toss Open API client credentials once, save them safely on the local machine, and use subsequent PAPER sessions without re-entry.

**Architecture:** Add a dedicated credential store/onboarding module. Keep raw secrets out of argv, logs, settings, account/order code, and demo mode. Resolve the new public path first while preserving the secure legacy path as a compatibility fallback. The root command launches PAPER only; setup validation uses OAuth plus one read-only price GET under the existing cross-process API lock.

**Tech Stack:** Python 3.12+, argparse, getpass, pathlib/os/tempfile, httpx MockTransport tests, Textual preview mode, pytest/Ruff/Pyright/Bandit/pip-audit.

### Task 1: Secure credential store

**Files:**
- Modify: `src/toss_market_terminal/config.py`
- Modify: `tests/test_config.py`

**Steps:**
1. Add failing tests for new/legacy path resolution, exact credential validation, `0700` newly-created directories, `0600` file mode, pre-existing parent mode preservation, no overwrite, atomic replacement, final/parent symlink rejection, hardlink rejection, and bounded errors.
2. Implement `CredentialStore` with same-directory temporary file, fsync, `os.replace`, strict ownership/mode/link checks, and no secret-bearing error messages.
3. Run `uv run pytest -q tests/test_config.py` and Ruff/Pyright on the module.

### Task 2: Setup and credential lifecycle CLI

**Files:**
- Create: `src/toss_market_terminal/onboarding.py`
- Modify: `src/toss_market_terminal/cli.py`
- Modify: `tests/test_cli.py`
- Create: `tests/test_onboarding.py`

**Steps:**
1. Add parser and interaction tests for `setup`, `credentials status`, and `credentials remove`.
2. Require a TTY for prompts, use normal input for Client ID and `getpass` for Client Secret, never accept secret argv, reject overwrite unless `--replace`, and require deletion confirmation.
3. Validate via injected async verifier in tests; production verifier calls token issuance plus `price("AAPL")` only.
4. Include `setup` in the API session lock boundary so concurrent live sessions block before prompting or mutation.
5. Verify no input value appears in stdout/stderr/exceptions.
