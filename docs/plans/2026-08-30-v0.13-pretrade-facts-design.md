# v0.13.0 — Pre-trade facts layer + order-flow design pass

## Goal

Make the moment right before a manual PAPER/LIVE order more useful (a
truthful "pre-trade facts" panel) and visually cleaner (a flat, compact,
high-contrast redesign of the order-flow modals), without adding any new
network endpoint, any new risk engine, or weakening any existing gate.

## Non-goals (explicit boundaries)

- No new endpoints (market calendar/session/warnings/fees/price limits/
  official sellable quantity). Anything not already derivable from existing
  GET paths or canonical preflight outputs is labeled UNAVAILABLE, never
  fabricated.
- No daily/monthly budgets, no $5 ledger, no automatic buy/sell/cancel/
  replace/retry.
- PAPER stays default; LIVE still requires the existing explicit command +
  env gate + interactive + quiet-arm + fingerprint-bound approval phrase.
- MARKET orders remain fully supported (BUY and SELL); nothing becomes
  LIMIT-only.
- No gradients / edge accent bars / left accent strips. Flat dark
  high-contrast only, matching the existing `#0d131a` dialog / solid
  single-color border convention already used across the app's modals.

## Architecture

### 1. `src/toss_market_terminal/pretrade.py` (new, pure, Textual-free)

Immutable models:

- `FactStatus` — `PASS | WARN | BLOCK | UNAVAILABLE`, with a Korean label
  (정상/주의/차단/정보 없음).
- `FactRow` — one line: `key`, `label`, `status`, `detail` (already-formatted
  Korean text; no raw account number/account_seq/token/order id/fingerprint
  ever goes into a row).
- `PretradeFacts` — `symbol`, `mode`, `side`, `order_type`, `as_of` (injected aware
  clock value), `rows: tuple[FactRow, ...]`, plus `overall_status`,
  `has_block`, `row(key)`, `to_privacy_safe_lines()`.
- `QuoteFactsContext` — the already-in-memory quote/orderbook inputs
  (`orderbook`, `last_trade_price`, `quote_timestamp`, `quote_fresh`,
  `orderbook_fresh`).
  `quote_fresh` is *not* recomputed here — it is the caller's existing
  canonical freshness truth (`TossMarketApp._interpretation_is_stale()`
  negated), passed in, so this module never duplicates the
  `PRICE_STALE_SECONDS` threshold.

Builder: `build_pretrade_facts(intent: OrderIntent, quote: QuoteFactsContext, *, now: datetime, open_orders: tuple[OpenOrder, ...] | None, mode: Literal["PAPER", "LIVE"] = "PAPER") -> PretradeFacts`.

`intent` is the existing `order_preview.OrderIntent` — the same frozen object
already carried by `OrderPreview` and (unchanged) by `LiveOrderPlan.intent`.
Reusing it means every field the facts layer needs (side, order_type,
quantity, limit_price, currency, symbol, holding_quantity,
cash_buying_power) is already validated/canonical; nothing is re-parsed from
raw provider JSON here.

Six rows, always in this order:

1. `quote_freshness` — PASS/BLOCK from the injected `quote_fresh` truth, plus
   a human-readable age computed from `quote_timestamp` vs `now` (display
   only, not a new threshold).
2. `best_quote` — best bid/ask/spread/spread% from the existing `Orderbook`
   already in memory. The app derives `orderbook_fresh` from the provider
   timestamp using the existing `price_stale_seconds` threshold; this pure
   module creates no second threshold. Missing/stale books are UNAVAILABLE and
   crossed books WARN.
3. `reference_price` — LIMIT: the limit price. MARKET: opposite best quote
   only when the book is fresh, complete, currency-matched, and not crossed
   (labeled an estimate, never a fill guarantee); otherwise last trade is an
   explicitly lower-confidence WARN fallback, else UNAVAILABLE.
4. `estimated_notional` — `quantity * reference_price` as `Decimal`, with
   explicit "not a fill guarantee / not a MARKET execution cap" wording.
5. `buying_power` (BUY) or `sellable_quantity` (SELL) — BUY keeps
   `RiskGate.estimate(intent)` as the only canonical blocking comparison. A
   larger top-of-book display estimate is WARN-only. LIVE account values are
   labeled PAPER-generation/last-known values and state that fresh account
   data is fetched only after Enter. SELL reuses
   `models.find_open_order_duplicates` (the canonical helper) to compute a
   conservative sellable estimate, explicitly labeled "추정, 공식 수치
   아님" — never relabeled as an official broker sellable quantity.
   UNAVAILABLE when `open_orders` is `None` rather than assuming zero.
6. `duplicate_orders` — same-symbol/same-side open-order state via
   `find_open_order_duplicates`; PAPER shows WARN while LIVE shows BLOCK when
   the last-known cache already contains a duplicate. An empty LIVE cache is
   WARN rather than PASS because the canonical gate performs a fresh GET only
   after Enter. This mirrors the canonical gate without preventing a local
   PAPER confirmation.

All Decimal/datetime inputs are validated fail-closed
(`PretradeFactsError`, a `ValueError`): non-finite, negative where
inappropriate, naive datetimes, and malformed ISO timestamps are all
rejected rather than silently coerced to zero.

The module reuses `render.py`'s pure `format_decimal`/`format_percent` helpers.
They have no Textual dependency and avoid re-deriving currency-aware decimal
and percent formatting.

### 2. Integration points (zero new network/account/order calls)

- `order_ticket.OrderConfirmScreen` (PAPER confirmation) gains an optional
  `facts: PretradeFacts | None` constructor argument and renders a new
  `#confirm-facts` section below the existing `#confirm-body` (which is left
  untouched so existing assertions keep working). It receives the remaining
  canonical tick-validity time and its absolute monotonic deadline; expiry
  changes the visible quote row to BLOCK and prevents Enter. The app callback
  independently rejects that immutable deadline even if a newer tick arrives,
  then also rechecks canonical stale state before storing a PAPER confirmation.
- `live_ticket.LiveApprovalScreen` (the primary redesign target) gains the
  same optional `facts` argument and is restructured into a flat compact
  hierarchy: header (PAPER/LIVE truth + symbol/side/type) → order core
  (quantity/price/notional) → facts section (PASS/WARN/BLOCK/UNAVAILABLE
  rows) → footer (isolated controls, unchanged quiet-arm timer behavior). If
  only optional facts are unavailable, the title says `부분 확인` rather than
  implying that every fact failed.
- `tui.py` builds the `PretradeFacts` object at the two call sites
  (`_on_paper_preview_built` → before pushing `OrderConfirmScreen`, and
  `_on_paper_confirmed` → before pushing `LiveApprovalScreen`) purely from
  state already resident on the app: `self.orderbook`, `self.current_price`
  as the last-trade fallback, `self.current_timestamp`, the negation of
  `self._interpretation_is_stale()`, and `self.portfolio_snapshot.open_orders`
  (when the snapshot's account matches and is not stale beyond trust — if
  unavailable, `open_orders=None` is passed through so the facts layer shows
  UNAVAILABLE instead of fabricating "no duplicates"). None of this triggers
  a new I/O call — opening either modal remains a pure read of in-memory
  state, verified by a test that asserts zero additional loader calls. The
  LIVE title and account/open-order rows call these values `last-known`; the
  existing `_submit_live_plan` fresh GET preflight still runs only after the
  armed Enter and remains authoritative.
- Both screens keep working with `facts=None` by showing one explicit
  `정보 없음` placeholder rather than attempting an incomplete calculation,
  so existing direct constructors such as `LiveApprovalScreen(plan)` remain
  compatible.

### 3. Visual design

- Keep the existing solid single-color dialog border (already flat, not a
  gradient or edge accent strip) and the existing `#0d131a` background.
- Replace the current loosely-spaced summary/details/help stack in
  `LiveApprovalScreen` with a denser block: one header line, 2–3 order-core
  lines, then one line per fact row (`LABEL · STATUS · detail`) with the final
  high-contrast palette (`#70d7a5` PASS, `#f0c36a` WARN, `#ff8f87` BLOCK,
  `#8996a5` UNAVAILABLE).
- Verify readability with deterministic `run_test` checks at 140×44 and
  90×30 (existing convention in `tests/test_tui_live_order.py` /
  `tests/test_order_ticket.py`), asserting dialog bounds, six fact rows, and
  `max_scroll_x == 0` at both widths.
