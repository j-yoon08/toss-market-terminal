# Toss Market Terminal v0.3 Implementation Plan

> **For Hermes:** Use subagent-driven-development and the isolated Ox worker to implement this plan task-by-task.

**Goal:** Upgrade the read-only single-symbol terminal into a practical personal market console with a persistent watchlist, local in-process alerts, and deterministic market-flow signals.

**Architecture:** Preserve the strict five-endpoint read-only boundary. Store non-secret user preferences in one bounded versioned JSON file, batch only the official `stocks`/`prices` endpoints (official maximum: 200 symbols), and keep WebSocket streaming focused on the currently selected symbol. All signals and alerts are deterministic observations, never trading advice or order execution.

**Tech Stack:** Python 3.12, asyncio, Textual/Rich, httpx/websockets, dataclasses, Decimal, pytest.

---

## Product contract

### Safety and scope

- No account, position, balance, order, correction, or cancellation endpoint.
- Never read or print credential contents. Ox must not access `/home/ubuntu/.config/tossinvest/openapi.json`, `.env`, auth stores, or production data.
- No background daemon, Telegram delivery, OS notification dependency, database, or order automation in v0.3.
- Alerts run only while `toss-market watch` is open and are shown as a Textual notification plus terminal bell where supported.
- Signals are factual labels derived from displayed data. Do not output BUY/SELL recommendations.
- Maintain compact terminal behavior. The watchlist may collapse/hide below the existing compact breakpoint rather than squeezing the orderbook/trades.

### Persistent settings

Default path: `~/.config/toss-market/settings.json`, overridable globally with `--settings PATH`.

Versioned shape:

```json
{
  "version": 1,
  "watchlist": ["AAPL", "NVDA", "005930"],
  "alerts": [
    {"id": "A1", "symbol": "AAPL", "kind": "above", "threshold": "250", "enabled": true}
  ]
}
```

Contracts:

- Missing file means empty settings.
- Symbols use existing `normalize_symbol`; preserve insertion order, reject duplicates, maximum 12 watchlist entries.
- Maximum 100 alerts. Decimal thresholds must be finite and positive.
- Kinds: `above`, `below`, `change-above`, `change-below`, `volume-spike`.
- `change-*` thresholds are percentage magnitudes; `volume-spike` threshold is a multiplier against the median of the previous available 1-minute candle volumes (minimum three baseline candles).
- IDs are monotonically allocated `A1`, `A2`, … from the existing file.
- Save atomically through a sibling temporary file and `os.replace`; create parent directory as `0700`, final file as `0600`; reject symlink settings files. Error messages must not echo raw file content.
- Preserve Decimal values as strings.

### CLI

Keep existing commands and add:

```text
toss-market --settings PATH watchlist list
toss-market --settings PATH watchlist add SYMBOL
toss-market --settings PATH watchlist remove SYMBOL

toss-market --settings PATH alert list
toss-market --settings PATH alert add SYMBOL {above,below,change-above,change-below,volume-spike} THRESHOLD
toss-market --settings PATH alert remove ALERT_ID
```

- Machine-stable concise text output; no credentials.
- Mutating commands are idempotent where sensible: adding an existing watchlist symbol reports it already exists without duplication; removing absent entries returns a clear nonzero validation error.
- `watch SYMBOL` ensures the launch symbol appears in the in-memory displayed watchlist, but must not persist it implicitly.

### Watchlist TUI

- Wide mode adds a left watchlist panel, maximum 12 entries, displaying symbol, latest known price/currency, and active-alert marker/count.
- Batch-refresh watchlist prices through `/api/v1/prices?symbols=...` at a conservative 15-second interval. Do not request per-symbol candles for background watchlist rows.
- The selected symbol continues to receive the existing full snapshot and two WebSocket topics.
- Up/Down (or j/k) changes the highlighted row; Enter switches the active symbol.
- Switching must cancel/await the previous feed task, reset symbol-scoped state, fetch the new snapshot, then start one new feed. No overlapping live streams, stale old-symbol tick application, or client recreation/token churn.
- Failed watchlist refresh keeps the last good rows and marks the panel stale without replacing the primary stream state.
- Compact mode hides the watchlist panel and preserves the existing orderbook/trades layout.

### Alerts

Pure evaluator inputs: alert rule, current snapshot/current price, computed market metrics/signals.

- `above`: fires on transition from below/equal to strictly above threshold.
- `below`: fires on transition from above/equal to strictly below threshold.
- `change-above`: fires when signed change percent crosses upward above the positive threshold.
- `change-below`: fires when signed change percent crosses downward below the negative threshold magnitude.
- `volume-spike`: fires when latest 1-minute candle volume ratio crosses upward above the multiplier.
- Edge-triggered per alert ID; no repeated firing while the condition stays true. Re-arm only after condition becomes false.
- On first observation, establish state without firing to prevent startup spam.
- An alert fires only for its symbol. Switching symbols must not leak evaluator state between symbols.
- TUI notification includes alert ID, symbol, objective condition, observed value, and timestamp; no recommendation wording.
- Show a bounded latest-alert line in the status area.

### Deterministic signals

Extend `MarketMetrics` or add `MarketSignals` with Decimal-safe optional fields:

- `orderbook_imbalance_percent = bid_volume / (bid_volume + ask_volume) * 100` over currently displayed levels.
- `bid_ask_ratio = bid_volume / ask_volume` when ask volume is nonzero.
- `vwap_distance_percent = (current_price - recent_vwap) / recent_vwap * 100` when recent VWAP is nonzero.
- `volume_spike_ratio = latest 1m candle volume / median(previous 1m volumes)` with at least three prior positive-volume candles.
- `trade_pressure_percent`: classify adjacent recent trades by uptick/downtick, weight by volume, and return uptick volume / directional volume * 100; unchanged ticks are excluded.

Neutral factual labels:

- Orderbook: `BID HEAVY` (>60), `ASK HEAVY` (<40), otherwise `BALANCED`.
- Trade pressure: `UPTICK HEAVY` (>60), `DOWNTICK HEAVY` (<40), otherwise `MIXED`.
- Missing/insufficient values display `—`/`INSUFFICIENT`, never fabricated zero.

Display these signals in the existing market stats panel with no extra colored edge bars or recommendation text.
